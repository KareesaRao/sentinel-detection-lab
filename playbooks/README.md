# Incident Response Playbooks

## Overview

This directory documents incident response workflows for the Microsoft Sentinel detection lab. The workflows describe how an analyst can investigate alerts generated by the lab's scheduled analytics rules, validate supporting evidence, and document findings.

## Investigation Workflow

1. **Review the incident:** Open the incident in Microsoft Sentinel and examine its severity, associated alerts, and MITRE ATT&CK technique.
2. **Identify affected entities:** Review the available host, user account, process, and other relevant entities.
3. **Validate the evidence:** Use KQL to query the relevant Log Analytics tables and verify whether the underlying events support the alert.
4. **Build a timeline:** Correlate event timestamps and entities to understand the sequence of observed activity.
5. **Document findings:** Record the detection rule, relevant evidence, investigation outcome, and any limitations.
6. **Recommend follow-up actions:** Where appropriate, recommend containment, remediation, additional monitoring, or detection-rule tuning.

## Lab Detection Scenarios

The lab includes detection rules for:

- Encoded PowerShell execution
- Scheduled task creation
- Registry Run key persistence
- Repeated failed logons
- Account discovery commands
- Windows Security event log clearing

## Investigation Principles

- Treat an alert as an investigative lead, not automatic proof of compromise.
- Distinguish simulated activity from real malicious activity.
- Validate findings against available telemetry.
- Avoid including sensitive identifiers, credentials, or confidential environment details in public documentation.

## Scope

This documentation describes an investigation workflow for a controlled lab. It does not represent a production incident-response engagement or an automated containment capability.
